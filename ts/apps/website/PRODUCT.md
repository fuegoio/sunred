# Product

## Register

product

## Platform

web

## Users

Developers evaluating or using Sunred. They arrive at the docs to get
started quickly, understand the API, self-host, or learn a specific feature.
They are technical, skim for answers, and expect code samples they can copy.

## Product Purpose

The documentation site is the reference surface for Sunred. It serves
getting-started guides, API reference (generated from the OpenAPI spec),
and self-hosting instructions. Success looks like a developer going from
zero to a running Sunred instance and a subscribed feed without needing
to ask for help.

## Positioning

A modern, fast, developer-friendly RSS reader with a clean API and multiple
interfaces. The complete package, not a single differentiator.

## Brand Personality

Warm and approachable, but task-oriented. The docs should feel like a
well-written manual from someone who wants you to succeed. Clear,
skimmable, with code samples front and center. Not chatty, not sparse —
confident and helpful.

## Anti-references

Documentation sites that bury the answer under marketing copy, require five
clicks to find the API reference, or use vague prose where a code block
would do. Enterprise docs that feel like they were written by a committee.

## Design Principles

- **Reading first.** Docs are reading material. Typography, line length,
  and spacing should make long-form guides comfortable to read.
- **Task-oriented.** Every page should help the user do something. Show the
  command, show the expected output, move on.
- **Complete, not cluttered.** The sidebar should be navigable without
  overwhelming. Search should work. Structure should be obvious.
- **Modern craft.** The docs site shares the product's visual vocabulary.
  No generic docs template look — it should feel like part of Sunred.
- **Accessibility is baseline.** WCAG 2.2 AA, keyboard navigation, good
  contrast, and reduced-motion support.

## Accessibility & Inclusion

WCAG 2.2 AA. Keyboard-navigable sidebar and search, screen reader support,
contrast ratios meeting AA minimums, and reading comfort: capped line
length for guides, adequate code block sizing, and reduced-motion
alternatives for any animations.
